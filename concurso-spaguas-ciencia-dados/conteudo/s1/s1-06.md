# SQL: JOINs, NULL e subqueries

> **Ideia central:** cada JOIN preserva um conjunto diferente de linhas; a prova cobra a contagem e o efeito do NULL, não a sintaxe.

## 1. Essencial

- **INNER JOIN.** Só pares que casam nos dois lados. Linha sem correspondência desaparece.
- **LEFT JOIN.** Preserva todas as linhas da esquerda; quando não há par, as colunas da direita vêm NULL. **RIGHT** é o espelho. **FULL** preserva os dois lados; **CROSS** faz o produto cartesiano.
- **Contagem de linhas.** Com A = 9 e B = 10: CROSS = 90. Se 6 linhas casam, INNER = 6, LEFT = 9, RIGHT = 10 e FULL = 13. Fórmula: `FULL = INNER + órfãos de A + órfãos de B`.
- **Fan-out.** Um join 1:N duplica o lado 1. Se um cliente tem 5 outorgas, `JOIN` gera 5 linhas para ele. Para contar clientes, use `COUNT(DISTINCT c.id)` ou `EXISTS`.
- **NULL não casa com NULL.** `ON a.id = b.id` é UNKNOWN quando um lado é NULL; a linha não entra no INNER.
- **LEFT JOIN + WHERE na tabela direita = INNER disfarçado.** `WHERE b.status = 'Ativa'` elimina as linhas em que b é NULL. Para manter os clientes sem outorga, a condição deve ir no `ON`.
- **COUNT depois do LEFT.** `COUNT(*)` conta a linha preservada mesmo sem par (retorna 1); `COUNT(b.id)` conta só as correspondências e retorna 0 para quem não tem par.
- **Subqueries.** Escalar retorna um valor; `IN` compara com uma lista; `EXISTS` testa existência; correlacionada referencia a query externa.
- **EXISTS × IN.** `EXISTS` evita duplicação; `IN` é legível para listas pequenas; desempenho depende do plano.
- **NOT IN com NULL.** Se a subquery retornar um NULL, `x <> NULL` é UNKNOWN e o `NOT IN` não retorna **nenhuma** linha. `NOT EXISTS` é seguro.

**Exemplo resolvido.** Clientes sem outorga, sem duplicação e sem o problema do NULL.

```sql
SELECT c.id_cliente, c.nome
FROM cliente c
WHERE NOT EXISTS (
  SELECT 1
  FROM outorga o
  WHERE o.id_cliente = c.id_cliente
);
```

Se `outorga.id_cliente` fosse nullable, `NOT IN` poderia retornar vazio por causa do NULL; `NOT EXISTS` não.

## 2. Quadro comparativo

| JOIN | Preserva | Linhas (A=9, B=10, 6 matches) | Quando usar |
|---|---|---|---|
| INNER | só pares | 6 | interseção |
| LEFT | toda a esquerda | 9 | “todos de A, com ou sem B” |
| RIGHT | toda a direita | 10 | “todos de B, com ou sem A” |
| FULL | os dois lados | 13 | diagnóstico de órfãos |
| CROSS | todas as combinações | 90 | combinações |

## 3. Pegadinha de prova

A FGV adora o LEFT JOIN que “vira INNER”: condição da tabela direita no WHERE remove os NULLs e iguala o resultado ao INNER. Também cobra `COUNT(*)` após LEFT JOIN, que devolve 1 para quem não tem par. Outra armadilha é `NOT IN` com subquery que contém NULL: o resultado é vazio, não é “todos os clientes sem outorga”. Por fim, “sem repetições” com join 1:N costuma pedir `EXISTS`, não `DISTINCT`.

## 4. Macete

**“LEFT preserva a esquerda; FULL soma os órfãos dos dois lados.”** Para NULL: **“NOT IN com NULL não devolve nada; NOT EXISTS devolve a verdade.”**

## 5. Questões

### Q1 — fácil

A tabela A tem 9 linhas e a tabela B tem 10. Qual é o resultado de `SELECT * FROM A CROSS JOIN B;`?

A) 9 linhas
B) 10 linhas
C) 19 linhas
D) 90 linhas
E) 0 linhas

**Gabarito:** D
**Comentário:** CROSS JOIN combina cada linha de A com cada linha de B: 9 × 10 = 90. As alternativas A e B confundem com LEFT/RIGHT; C soma em vez de multiplicar. CROSS JOIN não usa condição de igualdade e raramente é a resposta quando o enunciado fala em “relacionar” tabelas por chave.

### Q2 — média

`cliente` tem clientes sem outorga. Qual consulta lista todos os clientes e a quantidade de outorgas de cada um, mostrando 0 para quem não tem?

A) `SELECT c.nome, COUNT(*) FROM cliente c JOIN outorga o ON o.id_cliente = c.id GROUP BY c.nome`
B) `SELECT c.nome, COUNT(o.id) FROM cliente c LEFT JOIN outorga o ON o.id_cliente = c.id GROUP BY c.nome`
C) `SELECT c.nome, COUNT(*) FROM cliente c LEFT JOIN outorga o ON o.id_cliente = c.id WHERE o.id IS NULL GROUP BY c.nome`
D) `SELECT c.nome, COUNT(o.id) FROM cliente c JOIN outorga o ON o.id_cliente = c.id GROUP BY c.nome`
E) `SELECT c.nome, COUNT(*) FROM cliente c RIGHT JOIN outorga o ON o.id_cliente = c.id GROUP BY c.nome`

**Gabarito:** B
**Comentário:** O LEFT JOIN preserva todos os clientes; `COUNT(o.id)` ignora o NULL gerado pela ausência de outorga e devolve 0. Usar `COUNT(*)` (não mostrado com LEFT) devolveria 1 para quem não tem outorga. A alternativa C filtra justamente quem não tem par e perde os demais; E preserva as outorgas, não os clientes.

### Q3 — difícil

A coluna `outorga.id_cliente` aceita NULL e a subquery contém ao menos um registro com `id_cliente` NULL. A consulta `SELECT nome FROM cliente WHERE id_cliente NOT IN (SELECT id_cliente FROM outorga);` retorna:

A) todos os clientes sem outorga
B) um erro de sintaxe
C) apenas os clientes com outorga
D) uma linha NULL
E) zero linhas, pois o NULL da subquery torna a comparação UNKNOWN; `NOT EXISTS` resolve

**Gabarito:** E
**Comentário:** `NOT IN` é equivalente a uma cadeia de `<>`; qualquer NULL na lista torna o resultado UNKNOWN para as linhas comparadas, e o WHERE não as aceita. Por isso a consulta não retorna ninguém, mesmo havendo clientes sem outorga. `NOT EXISTS` ou `NOT IN (... WHERE id_cliente IS NOT NULL)` corrigem o problema.

## 6. Flashcards

- P: LEFT JOIN + condição da tabela direita no WHERE? | R: Vira INNER: as linhas sem par têm NULL e são eliminadas.
- P: COUNT(*) × COUNT(b.id) após LEFT JOIN? | R: COUNT(*) conta a linha preservada (1); COUNT(b.id) conta só pares (0).
- P: Por que NOT IN com NULL falha? | R: `x <> NULL` é UNKNOWN; se a subquery tem NULL, o resultado pode ser vazio.
