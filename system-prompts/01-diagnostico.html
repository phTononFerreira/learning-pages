ATO 1 · PENSAR / PÁGINA 01

O nó que perde 31% das mensagens

Um classificador de sete intenções parece trivial até você olhar a matriz de confusão. O que exatamente quebra quando o prompt é “óbvio”?

5 min Diagnóstico AnatomiaDiluição
01

O sintoma não é “prompt ruim”

A Loja Norte vende equipamentos de camping. O assistente no WhatsApp recebe 4 mil mensagens por dia e precisa mandar cada uma para uma de sete rotas. O prompt inicial tem seis linhas.

o número que abriu o incidente

31% das mensagens caem em outros. Dessas, metade vem de clientes que queriam apenas saber onde está o pedido. A equipe de operações passou a ler a fila manualmente - e o "assistente" virou um desvio caro.

Como ler esse número. Os 31% vêm da auditoria da fila real, antes do dataset. Já no golden set (base de teste curada e balanceada), esse mesmo prompt (v0/v1) manda 14,5% (9/62) para outros, enquanto o v4 cai para 9,7% (6/62). A diferença entre 31% e 14,5% vem da distribuição: a fila real tem mais casos ambíguos que o conjunto curado. Aqui, v0 retrata a produção e v1 marca a primeira medição no dataset.

v0 · system prompt
Você é um assistente da Loja Norte.
Classifique a mensagem do cliente em uma das
categorias: saudacao, duvida_produto,
status_pedido, reclamacao, cancelamento,
falar_humano, outros.
Responda em JSON.

O prompt “óbvio”. Roda sem erro, devolve JSON válido — e ainda assim erra o roteamento.

O QUE ACONTECEU
“e aí, tudo certo?”
→ outros · esperado: saudacao
“meu pedido 4412 atrasou e quero reembolso”
→ status_pedido · esperado: reclamacao
“como faço para cancelar?”
→ cancelamento · esperado: duvida_produto

Três erros diferentes. Nenhum é bug de infraestrutura.

O modelo não “desobedeceu”. Ele fez exatamente o que o texto permitia: escolheu a categoria que parecia mais próxima. O problema é que o prompt não definiu nenhuma fronteira — e o JSON só garantiu a forma, não a decisão.

02

System prompt é um contrato de decisão

Um bom system prompt não convence o modelo a ser inteligente. Ele reduz o espaço de decisão até sobrar uma resposta que o próximo nó consegue executar.

Pense em três camadas. Se qualquer uma falhar, o nó inteiro falha — mesmo que as outras estejam impecáveis.

CAMADA 1

Instrução

O que fazer, com que escopo e com que papel. “Classifique a última mensagem em exatamente uma das sete rotas. Não responda ao cliente.”

CAMADA 2

Fronteira

Onde uma classe termina e a outra começa. Definição positiva, contraexemplo, ordem de prioridade e o que fazer quando não dá para decidir.

CAMADA 3

Contrato

O formato exato da saída, o que é válido, o que fazer com o inválido. É a interface com o Flow — não um detalhe de estilo.

Abra cada bloco para ver a função, o que quebra quando ele falta e um exemplo de uma linha.

a distinção que organiza tudo

Instrução diz o que fazer. Fronteira diz onde parar — mas escrita de forma afirmativa: “use duvida_produto quando a pessoa pergunta como cancelar; use cancelamento quando ela pede para cancelar”. O modelo precisa de um critério observável, não de uma proibição.

03

Três falhas, três consertos

Quase todo classificador ruim falha em uma destas três dimensões. Diagnosticar a dimensão certa evita “consertar” o que não está quebrado.

FALHA 01 · TAXONOMIA

As classes se sobrepõem

Sintoma: o modelo escolhe entre duas classes plausíveis e a escolha parece aleatória.

Conserto: definição afirmativa + contraexemplo + ordem de prioridade. Se duas classes acionam o mesmo destino no sistema, junte as duas.

FALHA 02 · ATENÇÃO

Instrução demais

Sintoma: regras novas resolvem um caso e quebram outro; o modelo “esquece” uma regra do meio.

Conserto: uma regra por linha, poucas regras, dados por último, exemplos que ensinam a fronteira.

FALHA 03 · CONTRATO

O Flow não consegue ler

Sintoma: a resposta vem com preâmbulo, JSON truncado ou sinônimo; a condição do Flow nunca casa.

Conserto: enum fechado, saída curta, validação no código, retry único e fallback explícito.

“Mais texto” raramente é “mais controle”. Na maioria das vezes é mais superfície para o modelo ignorar.

04

O orçamento de atenção

Cada bloco que você adiciona compra alguma coisa e cobra outra. O objetivo não é o prompt mais completo: é o menor prompt que cobre as decisões reais.

Estimativa didática baseada em quantidade de blocos e tokens. Não é uma medição do Nova Lite — é um lembrete de que atenção é finita.

O prompt v0 traz só o papel, a lista de labels e o formato: cerca de 90 tokens. Ele é enxuto e mesmo assim erra. Ou seja, o problema não é o tamanho do prompt, mas o que entra nesse orçamento. Nas próximas páginas, adicionaremos apenas o que ajuda a separar as classes: fronteiras, prioridade e um contrato que o Flow consiga validar.

05

Checkpoint

Duas perguntas, sem consultar. Se errar, a explicação mostra a regra reutilizável.
