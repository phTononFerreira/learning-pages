01

O classificador é superfície de ataque

O roteador lê texto que qualquer pessoa escreve e devolve uma string que dispara um handler. A pergunta não é “o modelo obedece?”, é “o que acontece se ele obedecer?”.

Injection direta acontece quando o próprio usuário digita comandos maliciosos na mensagem. Injection indireta vem escondida em dados externos: observação de pedido, nome de produto, e-mail ou documento recuperado no contexto. Nos dois casos, o modelo enxerga apenas uma sequência de tokens — sem carimbo de origem. Para ele, instrução do sistema e dado do usuário são feitos da mesma matéria.

Delimitadores sozinhos não resolvem: são convenção de leitura, não fronteira de segurança. O ataque pode fechar a tag, imitar um papel ou pedir a repetição das regras. A hierarquia sistema > usuário ajuda a priorizar, mas não prova resistência — e, num modelo pequeno, obedecer ao texto mais recente é o que o torna útil.

a regra que fecha o buraco

O label não é uma autorização. cancelamento não cancela nada: ele escolhe um handler. O handler verifica identidade, pedido e política antes de agir. Saída do modelo é entrada não confiável — allowlist no parser, autorização no código, e nenhuma ação de alto impacto sem confirmação.

O Bedrock Guardrails entra como uma camada extra, mas traz dois detalhes importantes. Primeiro: para detectar ataques de prompt (prompt attack), você precisa demarcar explicitamente o trecho suspeito — usando blocos guardContent na Converse API ou tags equivalentes no InvokeModel. Sem essa marcação, a política ignora a mensagem do usuário. Segundo: o guardrail não inspeciona blocos toolResult nem toolSpec. Portanto, ele nunca substitui a validação de saída nem a checagem de permissões no código.

a conta que ninguém faz

Um milhão de chamadas, 1.000 caracteres e três políticas de content filter/denied topics: 1M × 1 × 3 = 3M text units. Com $0,15 por 1.000 text units, a conta fecha em ≈ $450. A inferência do Nova Lite, com ~650 tokens de entrada e 8 de saída, fica em ≈ $40 — o guardrail custa cerca de 11× o modelo. Se uma das políticas for prompt attack, a taxa é $0,08 e a conta muda. Valores aproximados, referência nov/2026; a latência adicional entra no p95.

03

Observabilidade e fallback

Em produção, o prompt é uma versão, um modelo, uma entrada, uma saída e uma decisão. Sem esses cinco no log, não se explica por que a fila humana cresceu.

Cada chamada deve registrar prompt_version (ou hash), model_id, hash da entrada, saída bruta, tokens, latência, confiança (quando disponível) e fallback_reason. O hash permite remover duplicatas e comparar execuções sem expor o texto original; a versão responde “esse erro começou depois de qual mudança?”. Se houver dados pessoais (PII), mascare-os antes de gravar o log e defina política de região e retenção.

Revise uma amostra de 1% a 5% do tráfego normal e 100% dos casos que caírem em fallback — afinal, ali o sistema já admitiu que falhou. Dispare alertas se o fallback passar de 5%, se a distribuição de labels mudar sozinha, se a latência p95 subir ou se a API sofrer throttling (limite de taxa). Faça o deploy em canary (1% → 5% → 25% → 100% do tráfego) com rollback testado, e congele o test set antes de abrir o primeiro 1%.
